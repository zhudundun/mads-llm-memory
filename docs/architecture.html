A Memory Layer for LLM Data-Science Agents
on ai-data-science-team

Notes from building a persistent memory layer for an LLM data-science agent stack. Five typed categories live in one SQLite file; a proactive wrapper retrieves and injects relevant rows before each LLM turn. Below: six experiments closing the gap between cold-start memory and a memory-aware agent that doesn’t leak across datasets, doesn’t memorize public CSVs, and computes when it should compute.

Design choices and lessons follow standard practice in the LLM-systems literature; sources are listed in References.

Key finding

Most failures of a memory-augmented agent are retrieval failures wearing other costumes — scope leaks, paraphrase misses, schema-data mismatches, memorization in eval, aliased writes. The six experiments below close each in turn; the scoreboard in §5 tracks the cumulative effect.

Caveat: 17 EDA scenarios is enough for direction-of-effect, not for population-level claims. Judge magnitudes are noisy; the load-bearing predicate is rubric/judge agreement.

mads is a persistent memory layer for ai-data-science-team (ADS). Five typed categories (preference, dataset, metric, data-quality, episode) live in one SQLite file; a proactive wrapper retrieves and injects relevant rows before each LLM turn. These notes record what changed in that layer across six experiments — 4.1 query-relevance gate · 4.2 declared axis model · 4.3 hybrid retrieval · 4.4 execution tool · 4.5 novel-data evaluation · 4.6 schema coupling — and what improved as a result. The Playbook distils ten rules for the next builder; Open work records what we deliberately did not ship.

1Setup

Agent stack, scenarios, variants, scoring.

  • Agent stack. business-science/ai-data-science-team — loader, EDA, viz, wrangling, cleaning, feature-eng sub-agents. mads wraps loader / EDA / viz; the others are unchanged.
  • Scenarios. 27 in total. This report focuses on the 17 EDA scenarios that exercise the memory layer: five original on the public Telco-churn CSV, plus twelve broad ones covering consistency, learning-from-feedback, efficiency, cross-dataset / cross-project isolation, multi-step chains, adversarial disambiguation, and one negative-recall scenario. Three scenarios were added during this work (cross_03, multi_03, adv_02).
  • Variants. Baseline = ADS with memory tools wired in but no proactive injection (the agent calls memory tools only if it remembers to). Memory-aware = the same agent driven by mads’s 8-step proactive wrapper, which retrieves and injects before each LLM call. The comparison is reactive vs proactive memory, not no memory vs memory.
  • Rubric. A programmatic check anchored to constants computed from the source CSV at import (e.g. TELCO_CHURN_PCT). The rubric tests against the data, not against a hand-typed expected value. Pass/fail per scenario.
  • Judge. A single-shot LLM grader (Claude Sonnet 4.6, same family as the agent) scoring both variants 1–5 with chain-of-thought. Read for direction only — pairwise LLM judges get direction right but magnitude noisy[1]. The load-bearing predicate is agree: rubric and judge should pick the same winner.

2The memory layer

Layered overview, categories, proactive flow, contracts.

2.1  Layered overview

Two wrapper families bracket the LLM. Reactive wrappers nudge the LLM to call memory tools and observe what happens. Proactive wrappers retrieve before the LLM runs and inject the result. The cull-then-inject stance is deliberate: long-context models do not eliminate the need for selection[1].

2.2  Categories and scoping

Tenancy is a declared axis model, not per-category ad-hoc. Each category declares how it relates to three axes (USER, PROJECT, DATASET) using four roles — identity-required, identity-optional, audit, reference. Stores filter on identity axes; audit axes are recorded but not filtered. The cognitive split between semantic memory (cats 1–4, versioned) and episodic memory (cat 5, append-only) is the same split Park et al.’s Generative Agents use[2] — here it is a schema constraint rather than an emergent property.

2.3  Proactive flow

Steps 1–4 and 6–8 are deterministic Python; step 5 is the single LLM call. The flow is deliberately not agentic — decomposing one big prompt into a multi-step pipeline is the same gradient that took AlphaCodium from 19% to 44% pass@5 on CodeContests[1]. Step 7 (auto-extraction) is deferred because it would re-introduce non-determinism on the write path; see §8.

  1. Build dataset context — profiler.profile(df, dataset_name)
  2. Retrieve relevant memories — manager.retrieve(query, user_id, project_id, dataset_fingerprint, k)
  3. Format memory context — manager.format_context(memories) → [memory:cat:id] blocks
  4. Inject context into prompt — user input + profile summary + memory block + nudges
  5. Call base agent — handle.invoke(…, extra_tools=manager.all_tools(…))
  6. Validate output — warnings only (stubs)
  7. Extract candidate memories — deferred
  8. Return result + memory trace — reads / writes / injected / warnings

2.4  Contracts (don’t break these)

  • Scoping is a declared axis model. Tool factories close over tenancy; the LLM never sees it.
  • Versioned vs append-only by event-ness. Definitions version via valid_to; events are append-only with embeddings.
  • DataFrames travel by reference. Rows hold URIs or content-addressed fingerprints. Inline pickled dataframes are forbidden.
  • ADS wrapped, not imported. Only the adapter (and eval/) may import ai_data_science_team.
  • One SQLite, no second vector store. Cats 3 and 5 share one sqlite-vec virtual table family and one embedder instance.
  • Categories must not import each other. Schema coupling lives in the manager (see §4.6), not in cross-imports.
  • Query-relevance gate at the hybrid layer. One location; sub-retrievers stay query-agnostic.
  • Concurrency: store-owned RLocks + WAL. One shared lock when stores share a connection.

4Closing the gap

Six experiments, in order. Each closes a scenario; the takeaway generalizes.

4.1  Query-relevance gate at the hybrid layer

Hypothesis. Preferences are always-on user state, returned for every query at score 1.0 by design. Without a relevance gate above the sub-retrievers, every query — including queries that are not data-shaped — receives the full preference set, and the LLM dutifully cites them.

Mechanism. A deterministic, keyword-based query classifier runs above the four sub-retrievers in the hybrid retriever. Non-data queries short-circuit to an empty list uniformly. The locked design (preferences as always-on user-state) is preserved; the gate operates above the per-category retrievers, not inside them.

neg_01 — preferences injected: 3 → 0 · [memory:…] citations in response: 3 → 0 · rubric: fail → pass

Outcome: shipped. The concept extends to context-as-sculpture: the k-cap on returned rows is the second chisel, and the Lost-in-the-Middle finding[6] is part of why we don’t inject every row that scored above zero. Takeaway: retrieval needs a relevance gate, not just rank-by-score. One gate above the sub-retrievers, not per-category.

4.2  Declared axis model for tenancy

Hypothesis. Per-category ad-hoc tenancy drifts: a preference scoped only by user surfaces in every project; a metric scoped only by project surfaces on every dataset. Each category’s filter is locally correct; the system as a whole leaks. A uniform declaration is needed.

Mechanism. Three axes (USER, PROJECT, DATASET) crossed with four roles — identity-required, identity-optional, audit, reference. Each category declares its mix once. Preferences picked up project- and dataset-optional axes plus the LLM-visible project_scoped / dataset_scoped behaviour selectors. The data-quality category re-anchored to dataset fingerprint, so the same dataset in two projects shares one issue library. Retrieval filters “NULL or equal” and surfaces the most-specific eligible row.

cross_01 — “customerID” in B’s response: 1 → 0 · rubric: fail → pass · judge base/mem: 3 / 4
cross_03 (new) — rubric: pass · judge base/mem: 3 / 4

Outcome: shipped. Residual: if the LLM forgets to pick dataset_scoped=True when teaching a dataset-specific rule, the row is stored as global and the leak can recur — prompt-engineering surface, not memory-layer bug. Takeaway: tenancy is a declared axis model, not a per-category ad-hoc. The closest analogue is multi-tenant database design rather than published LLM-memory writing.

4.3  Hybrid retrieval — a semantic leg on the metric retriever

Hypothesis. String-shape retrieval (exact, substring, tokenized) misses paraphrase: the stored metric is qualified_customer; the user asks “qualified customers.” Three string strategies score 0. Adding more string rules is whack-a-mole; semantic similarity generalizes across surface form.

Mechanism. A semantic leg on the metric retriever — embeddings of name + business definition, stored alongside the row. Merged per-metric with max(string, semantic): either signal is enough. The semantic and episode embedders share one model load. The pattern (BM25 ⊕ dense, merged by max) is the production default for RAG — string-only misses paraphrase, semantic-only blurs exact names like IDs[4].

multi_01 — metric retrieved: no → yes (semantic similarity clears the noise floor)

Outcome: partial. The metric now reached the prompt, but multi_01 still didn’t produce a number — the LLM had the definition and no surface to apply it. That gap is the subject of 4.4. Takeaway: string-shape retrieval is whack-a-mole; semantic similarity generalizes. Either signal is enough; the max-of merge keeps both, and is the cheapest defensible default.

4.4  Execution tool: run_pandas_code

Hypothesis. Memory surfaces the right rule. The LLM cites the rule. Then it bails out without producing a number. Diagnosis: knowledge in memory is necessary but not sufficient — if every tool in the agent’s belt is a descriptive whole-dataframe aggregate, the LLM has no surface on which to apply a filter.

Mechanism. A subprocess-sandboxed tool over a def compute(df) -> dict contract, wrapping ADS’s existing sandbox via the adapter. The tool is not a memory category — it is an execution surface. The factory is bound to the current dataframe so a mid-conversation rebind is honoured.

multi_01 — final answer: missing → 21.7% exact (cites memory metric; calls tool twice)
multi_02 — counts: 1473 / 1684 (memorized) → 1472 / 1685 exact

Outcome: shipped. A new (rarer) failure mode appears: “the LLM had the rule and chose not to compute.” That’s a prompt-engineering surface; monitored via judge direction. Takeaway: knowledge in memory does not imply ability to apply it; the tool surface is part of the agent contract. Memory-layer correctness alone does not produce correct answers.

4.5  Novel-data evaluation

Hypothesis. The Telco-churn CSV is public enough that the LLM has plausibly seen it during training. The off-by-1 pattern in multi_02 (1473 / 1684 vs 1472 / 1685) is the data-science analogue of regurgitation. Without a check on data the LLM has never seen, “close to ground truth” cannot be distinguished from “reciting from training.” Yan’s eval writeup uses longest-common-subsequence on mid-book passages for the same diagnostic intent[5].

Mechanism. Added multi_03_synthetic_filter: a 120-row deterministic synthetic sales dataset (seed = 42) the LLM cannot have seen. Session A teaches a project-specific definition; session B asks the mean amount of premium orders. The LLM has to compute — no training-distribution number to recite.

multi_03 — premium_order mean amount: $399.39 exact (ground truth $399.39238095)

Outcome: shipped as a scenario. The broader principle: any rubric tolerant of small error needs a novel-data check; otherwise memorization passes as success. Takeaway: evaluation rubrics tolerant of small errors mask memorization; exact match on counts — ideally on data the LLM has never seen — is the safer signal.

4.6  Schema coupling between dataset and metric categories

Hypothesis. The memory layer holds two halves of a contract — a definition (a metric’s rule) and a schema (the dataset’s columns) — but never cross-checks them. When the data cannot satisfy the definition, the LLM proxies silently with whatever column is at hand and reports a number. The substitution may then get saved back, contaminating memory.

Mechanism. Coupled the dataset and metric categories at retrieval time, without cross-imports. The metric category gained a required_columns field (LLM-declared or auto-parsed from the SQL definition). The manager resolves available columns from the bound dataframe (preferred) or from column memory (fallback). The metric retriever decorates each result with applicable + missing_columns; the formatted context emits APPLICABLE: false (requires …) so the LLM sees both the metric and the gap. Wrapper nudges strengthen the “do not silently substitute” instruction. This is the “andon cord” pattern applied to definitions that no longer fit their data[1].

adv_01 — silent substitution + contaminated save → cites inapplicability and asks the user; clean store. Judge base/mem: 3 / 5.
adv_02 (new) — LLM cites the applicable metric and runs the tool; reports 1,441 exact. Judge base/mem: 3 / 5.

Outcome: behaviour shipped; live re-runs are correct. Rubric still fails on adv_01 / adv_02 for parser-level reasons unrelated to memory (a regex can’t distinguish the LLM’s own assertion from a verbatim quote of the user’s definition; a number extractor grabs the wrong cell). We chose not to hand-tune the rubric — rewriting an assertion to make a behaviorally-correct run pass would be Goodhart’s Law in miniature[1]. Aliased-name contamination (active_user / active_users) was an upstream symptom that disappears because the LLM no longer feels pressure to substitute; the downstream normalizer hardening is in §8. Takeaway: the memory layer must surface schema mismatches before the LLM is asked to use a definition. Two halves of a contract in two stores require an explicit cross-check at retrieval — couple in the manager, not via cross-imports.

6Discussion

The taxonomy underneath, and four cross-cutting observations.

6.1  Six failure modes, generalized

Each experiment closed a specific scenario, but the underlying patterns generalize. None of them are specific to memory-augmented data-science agents — they apply to any system with three ingredients: an LLM, a persistent state store, and a finite tool surface.

Failure modeWhat it isClosed by
Retrieval mismatchStorage keys differ from query forms. Pure-string retrieval misses paraphrase.4.3
Scope leakageTenancy implicit. Each category’s filter locally correct; the system as a whole leaks.4.2
Silent substitutionTwo halves of a contract live in different stores and never cross-check.4.6
Memorization as evalFamous datasets make “close enough” indistinguishable from “reciting.” Off-by-1 is the tell.4.4 + 4.5
Knowledge ≠ executionMemory surfaces the rule; tool surface has no way to apply it.4.4
Aliased contaminationVersioning relies on identity; plural/singular variants create duplicate active rows.upstream 4.6; downstream open

6.2  Cross-cutting observations

  • The memory layer is one piece of the agent contract; the tool surface is another. 4.4 was forced because 4.3 alone wasn’t enough.
  • Coupling between categories belongs in the manager, not in cross-imports. 4.6 surfaces the schema gap by composing two stores at retrieval time; neither store imports the other.
  • Eval design carries as much weight as memory design. 4.5 (novel data) and the two-signal agree predicate did more for confidence than any single retriever change.
  • The deterministic flow is the rate-limiter for diagnosis. Because steps 1–4 and 6–8 are Python, a regression in retrieval surfaces at the right step rather than hiding inside the LLM call.

7Playbook

Ten rules for the next builder, extracted from the experiments.

  1. Declare scoping axes at category birth. USER / PROJECT / DATASET × identity-required / identity-optional / audit / reference. Picking the mix later means rewriting the schema.
  2. Pick versioned vs append-only by event-ness. Definitions version via valid_to; events are append-only. Don’t reach for either reflexively.
  3. Hybrid retrieval, merged by max. Run a string leg and a semantic leg; either signal surfaces the row. Pure-string misses paraphrase; pure-semantic blurs exact names.
  4. One relevance gate above the sub-retrievers. Not per-category. The gate says “this query isn’t data-shaped — return nothing.”
  5. The tool surface must include execution, not just description. Knowledge in memory is necessary, not sufficient: the agent needs a way to apply what it recalled.
  6. Anchor rubrics in ground truth computed from data, not hand-typed. Use the LLM judge for direction only; magnitude is noisy.
  7. Test on data the LLM has never seen. Off-by-1 in opposite directions is the memorization tell. A seeded synthetic dataset is the cleanest immunization.
  8. Surface schema mismatches at retrieval, not after computation. If a definition needs a column the dataset doesn’t have, decorate the result with applicable: false — don’t let the LLM proxy.
  9. Concurrency at the contract layer. Per-store RLocks + WAL; when stores share a connection, share the lock. Don’t paper over BEGIN within BEGIN at runtime.
  10. Honest residuals. When behaviour is right and a rubric is wrong, fix the rubric only if it’s worth optimizing for the measure. Otherwise label it and move on — the alternative is Goodhart.

8Open work

What we deliberately did not ship, and why.

Auto-extraction (deferred)

Step 7 of the 8-step flow. An LLM-driven extraction layer would re-introduce non-determinism on the write path; one bad extraction can corrupt a category for the rest of its lifetime — the aliased-contamination failure mode in §6. Add it only after “what gets saved?” is reviewable at the contract layer.

Stem-aware identity normalizer. Open. 4.6 upstream-relieves the symptom because the LLM no longer feels pressure to save plural variants; the duplicate-row vulnerability remains until the normalizer collapses plural / singular and similar trivial variants.

Long-horizon / multi-turn coverage. Current evals are 2-session pairs (A teaches; B asks). Longer chains (A teaches; B refines; C asks under conflicting constraints) are not exercised. Expect new failure modes around versioning conflict resolution.

adv_01 / adv_02 rubric residuals. Both are parser-level: a regex can’t distinguish the LLM’s own assertion from a verbatim quote, and a number extractor grabs the wrong cell. Behaviour is verified correct on live re-run and on judge; we preserve the rubric-fail label rather than hand-tune.

Categories 6–9. workflow_recipe, pipeline_decision, experiment_record are event-style and should re-use the cat-5 append-only pattern. Versioning is not a category; cats 1–4 already cover that.

Dataset-scope drift on writes. If the LLM forgets to set dataset_scoped=True when teaching a dataset-specific rule, the row is stored as global and the leak can recur. The retrieval-side fix is shipped; the write-side guard is a prompt-engineering surface.
